Visual update — what still looks old

Every window, menu and panel of the app was checked against the new design (the E:\Teamz HTML designs). These are the pieces that still use the old look. Each one shows a real picture, where you meet it in the app, what is old, and the file to change.

Old UI still in the app

Pictures:
01

Solution Editor window

Board toolbar → double-click Solution, or Solutions panel → right-click → Edit my solution…
High
Rendered from the current code with sample sections. In the app it also has a plain Windows title bar.

What is old

  • The last big window on the pre-redesign look: a plain Windows dialog with a standard title bar, not a Schemax card.
  • Its own colour set: Tailwind blue #3b82f6 for Save and focus, grey #f8f9fb background. Not the teal #0d847d of the new design.
  • Stock tree and buttons: flat ▲ ▼ arrows, small outline buttons, a table header like a spreadsheet.
  • Section names in bright blue; no icons, no counts, no empty-state help.

Where in the code

src/ui/SolutionEditorDialog.cpp (2,744 lines) — colours in dialogStyle() at line 99.

Suggested update

Rebuild it as a card in the new style, like Settings and Help: navy/teal tokens, a section list on the left with counts, entry rows with net chips, the notes editor on the right, and Save/Revert in a footer. The handoff notes it as “the only user-visible screen still on the pre-redesign UI”.

02

Text prompts (“Create First Section Name”, rename…)

Board → right-click a net → Add Net to Solution when no section exists yet; new section / rename inside the Solution Editor
High
The stock Qt prompt with the app's old popup style. In the app it sits in a plain Windows title bar.

What is old

  • The stock Qt input box (QInputDialog): no Schemax card, no icon, three lines of help squeezed above the field.
  • Old VS Code-blue buttons #0078d4 from the old popup style.
  • Every other question in the app already uses the new Notify card — these three are the leftovers.

Where in the code

SolutionEditorDialog.cpp lines 1254, 1545, 1729 · style AppTheme::getPopupDialogStyle() at apptheme.cpp:843.

Suggested update

Add a one-field “ask” card to the new Notify family (same card as the confirm dialogs, with an input and example chips such as BL_LIGHT · DISPLAY · POWER RAILS), and use it in these three places.

03

Board right-click menu

PCB viewer → right-click a pin or part (Find Net · Find Component · Add Net to Solution · RFFE test points)
High
Cropped from an older screenshot (docs/Solution Editor.png). The board behind it is older, but this menu's code is unchanged, so it looks the same today.

What is old

  • A native Windows menu (AppendMenuW / TrackPopupMenu), not a Qt menu — so it can't follow the app theme at all.
  • Stays light grey in dark mode; no icons; a “Cancel” row.
  • Every other menu in the header now uses the new dropdown panel.

Where in the code

src/viewers/pcb_new/qt/PCBNewViewerWidget.cpp around line 6300 (ID_FIND_NET, ID_FIND_COMPONENT, ID_ADD_NET_SOL, ID_RFFE_*).

Suggested update

Replace it with a themed popup in the new style: net and part names in mono chips, icons (search, chip, plus), RFFE rows grouped under an eyebrow, and no Cancel row (Esc / click away).

Share one new-style context menu with item 03: teal hover wash, the selected text as a chip at the top, “Find on board” rows with the board name as small grey text.

06

Net info bar at the bottom of the board

PCB viewer → click a pin → the “NET: … · N connections ×” bar along the bottom
Medium
Cropped from an older screenshot (docs/boardview viewer.png). The painting code is unchanged, so it still looks like this.

What is old

  • Painted with fixed colours: a light-blue gradient rgb(240,244,252) and a sky-blue border #4fc3f7.
  • Stays light in dark mode — it never reads the theme.
  • Fonts set in points (8/9/10 pt), unlike the pixel sizes of the redesigned board UI (net panel, hover card).

Where in the code

PCBNewViewerWidget.cpp:11941 — drawNetInfoBar().

Suggested update

Restyle it as a glass pill matching the board toolbar dock: theme colours, the net name in mono, the connection count as a chip, and the same close button as the net panel.

08

Solutions side panel (PCB viewer)

PCB viewer → Solutions button → the docked panel on the right with sections, lines and the notes card
Low
No picture here — this panel only draws inside a running PCB viewer with a solution loaded, so it can't be rendered on its own. Open a board with a solution and take a screenshot to complete this card.

What is old

  • Restyled once, but with a different system — “Technical Precision” from UI/DESIGN.md (deep navy and amber markers) — not the Teamz design used everywhere else.
  • Its right-click menus (item 05) were never moved to that palette.
  • The handoff lists the design's SolutionsPage (1,208 lines) as never ported.

Where in the code

PCBNewViewerWidget.cpp:2201 (SidebarTokens) and setupSolutionsPage().

Suggested update

Do it together with the Solution Editor (item 01) so reading and writing a solution look the same.

Worth fixing at the same time (not old design, but inconsistent)

  • Header “Help ▾” menu still opens the small Help dropdown, while the rail, the library and F1 now open the new Help Center. Point it at the Help Center too.
  • Tools without a design — UART Terminal, Panic Checker / Flash iOS and RFFE were built in the app and borrow the Chip Finder look. They are not old, but no E:\Teamz design exists for them yet.
